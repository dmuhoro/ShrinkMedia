## What This Means For New Work

- **The on-device invariant is structural:** the manifest has no INTERNET
  permission. Adding network = ADR (Article II.2).
- **The core media/PDF paths are device-verified** (C3/C4/C9/C10/C12/C14 hold on-device PASS),
  and the appliance is feature-complete for its scope — ShrinkMedia is in **maintenance mode after
  v0.9.0** (confirmed ACTIVE 2026-09-05; new feature work lives in the Forge/DataBank/EasyTutor
  repos; see `docs/operations/shrinkmedia-stop-point.md`).
- **The 2026-09-05 directive is answered in doctrine + code** (Sprint 21, C25): RSI requirements
  with the **Owner as sole authorizer — dial 0/OFF**, nothing may self-authorize
  (`rsia-program.md`); a measurable build loop (`measurement.md`); the "steal like an artist"
  workbench (reuse ledger, `skills-workbench.md`); hardware optionality via **ADR-016** host tiers
  (Elitebook 2540p = bare-metal Debian 13, no hypervisor — SEP=storage-vs-processing split preserved).
- **The first working ecosystem piece exists:** DataBank `dvault` (append-only vault, journal-backed,
  19 tests) in its own private repo; run it daily per `RUNBOOK.md` — that daily proof is the
  **ecosystem roadmap's Checkpoint A** and the only calendar-bound dependency left before the
  stargate milestone.
- **Nothing under C11 may be claimed as *hardware-delivered*.** It is now
  **implemented and build-verified** (fail-closed gate + real GenAI path, no
  INTERNET) but the actual on-device inference has **not** run on Nano hardware —
  that's L5 and requires a Nano/AICore-capable device. C12 OCR is
  implemented **and** device-verified (reads "SHRINKMEDI" on API 36;
  `docs/evidence/2026-08-31_device_verification.md`).
- **Release signing is complete.** The production keystore
  (`~/.android/keystores/shrinkmedia-release.jks`) is generated; `keystore.properties`
  references it and is gitignored (fail-closed if absent). `apksigner verify` PASS on
  the v0.3.0 `app-release.apk`. **Backup the keystore off-machine — it is the app's
  permanent identity and cannot be recovered if lost.** A verified checklist with the
  live checksum anchor now exists (`docs/runbooks/keystore-backup.md`); performing the
  off-machine copy is a human step not yet completed.
