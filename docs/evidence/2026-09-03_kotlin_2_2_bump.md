# Evidence — Kotlin 2.0.21 → 2.2.0 bump (L4a)

**Date:** 2026-09-03
**Status:** PASS (host regression: compile + unit + lint + androidTest-compile all green)

## Why

The ADR-011 on-device AI surface needs ML Kit GenAI Prompt (`com.google.mlkit:genai-prompt`).
That artifact and its `genai-common` core are compiled with **Kotlin 2.2.0** (metadata 2.2.0),
which the project's Kotlin 2.0.21 compiler cannot read (reads metadata ≤ 2.1.0) and rejects with
`Module was compiled with an incompatible version of Kotlin`. Bumping Kotlin is the prerequisite
to consume the real library — without it, any attempt is a false/broken path.

Compatibility (Kotlin Gradle plugin / AGP / Gradle tables, 2026):
- Kotlin 2.2.0 supports AGP 7.3.1–8.10.0 and Gradle 7.6.3–8.14. Our AGP 8.9.1 + Gradle 8.11.1 are in-range.
- Compose compiler ships with Kotlin ≥2.0, so `org.jetbrains.kotlin.plugin.compose` must match (2.2.0).

## Change

`build.gradle.kts`:
- `org.jetbrains.kotlin.android` 2.0.21 → 2.2.0
- `org.jetbrains.kotlin.plugin.compose` 2.0.21 → 2.2.0

## Honest caveat

- One deprecation warning surfaced: `jvmTarget: String` is deprecated in favor of the
  `compilerOptions` DSL (`app/build.gradle.kts:61`). It is a warning, not an error, and does not
  fail the build; migrating to `compilerOptions {}` is a cosmetic follow-up and did NOT block this
  bump (kept the change minimal and isolated).
- This bump by itself adds no user-facing behavior; it only makes the toolchain able to link the
  GenAI library that Layer 4b introduces.
